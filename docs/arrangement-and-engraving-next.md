# 一つの旋律から、編成に合わせて弾ける譜面を作る

最初の到達点は、同じ16小節をアコーディオン独奏と二重奏に編曲し、奏者がA4の譜面を見て弾き比べられること。独奏では一人の両手に曲を収める。二重奏では句末のモチーフを相手に渡し、主旋律が戻るところで伴奏を薄くする。この違いを音と紙の両方で確かめてから、室内楽と長い曲に広げる。

## 実装の出発点

計画の基点は2026年11月20日に確認した `main` の `8e87ab76`。実装はこの履歴を含むブランチから始める。

- 編曲には、和声・リズム・対旋律を組み合わせる `suggest_integrated_arrangements`、セクション別の声部配置、確定した案を再生成する仕組みがある。独奏では `screen_harmony_groove_standard_bass` を使える。これは指定楽器の左手ボタンで各時点の響きが再現できるかを調べる。前のボタンから手が届くか、左右を合わせて弾けるかは別途確かめる。
- 清書には、総譜・パート譜のレイアウトを決める `compute_print_layout_for_view`、ページSVGとベクターPDFの出力がある。印刷比較用の既存10曲では、文字の小ささや最終ページの余白が課題に挙がった。実装前に同じ用紙・フォントで再出力し、現在も再現する箇所を選ぶ。

## 実装順と完了条件

| 段階 | 作るもの | 完了の判断 |
| --- | --- | --- |
| 1　比較用の譜面 | 弱起、句末の休符、タイ、途中のコード変更を含む16小節を1曲選ぶ。現行版の演奏、MusicXML、A4のSVG・PDFと、音や紙面で気になる小節を保存する。 | 同じ入力・設定で再出力できる。旋律の音高と発音時刻、拍位置、印刷上の記号を元譜と照合できる。 |
| 2　独奏と二重奏 | 独奏では低音と和音の交替、右手に残す内声、難所で省く音を選ぶ。二重奏では旋律、応答、低音をフレーズ単位で受け渡す。既存のコード候補から各編成で演奏できる案を選び、固定した和声と旋律を守る。 | 同じ旋律から独奏譜と二重奏の総譜・各パート譜を出せる。音域、同時発音、指定楽器のボタン、声部を渡す拍を検査し、候補を作れない場合は小節と理由を返す。 |
| 3　拍と声部を読みやすくする | 生成した伴奏で判断しづらい箇所から、拍のまとまりに沿う連桁、休符とタイの分割、複声部の符尾・休符の置き方を改善する。まず4/4で裏拍から伸びる音、次に6/8の3+3と5/8の2+3・3+2を扱う。 | 清書前後とMusicXML往復後でパート別の発音時刻・長さ・音高・強弱が一致する。付点、タイ継続、連符、弱起の正例を用意し、手で指定した連桁や声部を守る。 |
| 4　紙面と譜めくり | 和音記号と旋律、歌詞と低い音符、強弱記号とヘアピンが重なる例を一つずつ直す。総譜とパート譜は別々に改段し、パート譜では休みの長い箇所を譜めくり候補にする。 | 同じA4実寸で対象の重なりが解消し、文字の欠落や裁ち落としがない。固定改行・反復・括弧・ページをまたぐタイを確認する。指定テンポでめくる余裕がない場合は該当箇所を示す。 |
| 5　曲全体の展開と別編成 | 独立に作曲した32小節で、AのモチーフがBで応答に回り、A′で主役に戻る案を作る。室内楽三重奏を加え、持続音を支える声部、リズムを刻む声部、休む声部を選べるようにする。 | 初出・対照・再現の区間で、指定した役割の違いが実際の発音と各パート譜に表れる。区間再生成で固定小節と範囲外の音が保たれ、反復展開後も保存した案を再現できる。 |

段階2と3は同じ16小節で並行して進める。**最初の試奏は段階3の直後**に置き、奏者がつまずいた小節を記録する。音の届きにくさなら編曲へ、拍や声部の読み違いなら清書へ戻す。段階4では実際の改ページを含む長さの既存曲も使う。

## どこに実装するか

編成別の音の選択と譜面用の音価分割は `acorde-core` に置く。清書で一つの音をタイに分ける場合は演奏イベントを照合する。段・ページの割り振りは `acorde-layout`、記号の描画は `acorde-render-svg`、PDFの最終出力は `acorde-pdf` が受け持つ。SVGだけで直った箇所も、同じ位置をPDFで確認する。新しい編成と自動清書は明示指定で使う形から始める。

各段階で該当クレートの固定譜例を検査し、統合時に `cargo test --all` と既存のChrome full/viewer WASMテスト・容量検査を通す。編曲はRustとWASMでパート・発音時刻・長さ・音高・強弱を突き合わせる。

## 音と紙面の評価

- **編曲**　同じ編成内で現行版と新案を、同じテンポ・音源・音量で匿名化して聴き比べる。奏者には「旋律が追えるか」「応答が自然か」「指定の楽器で無理なく弾けるか」を別々に記録してもらう。異なる編成どうしの好みは自由記述に残す。
- **清書**　演奏内容を固定し、現行版と新版を同じ用紙・倍率で印刷する。拍を読み違えた位置、記号の重なり、譜めくりに間に合わない箇所を小節番号で残す。既存の10曲とVerovio 6.4.1の比較記録も使い、抽出した重なり候補は実寸のPDFで確かめる。
- **採用判断**　開発に使わなかった曲を先に確保し、最後に少なくとも2人が順序を伏せた比較を独立に評価する。固定旋律の変化、指定条件で弾けない音、必要な記号の欠落があれば該当段階へ戻す。聴感や読みやすさで評価が割れた場合は、曲・編成・小節ごとの結果を残し、既定値の変更は保留する。

『Aloha Oe』では長い作曲者名を曲名の次の行に置いた。歌詞の衝突を避けて移動した音節が下の五線にかからないよう、描画位置から必要な譜表間隔を求める。A4の3ページ・5段、全146個の歌詞を保ち、歌詞の文字サイズは3.08 mm。複声部の休符の上下位置はMusicXML往復で照合した。固定改ページをまたぐタイと一番括弧は、前後のページのSVGと、反復で戻る譜めくりの診断を検査する。

最終比較には開発に使わなかった8小節の Orchard Gate を使う。独奏は内声の有無、二重奏は旋律の受け渡しと句末の応答を、同じ伴奏設定で聴き比べる。清書の比較では同じ演奏内容のまま、旧版と新版で出力したPDFを読む。奏者二人の回答を受けて、音選びの修正と記譜の修正を小節ごとに判断する。

ローカルのmacOSでは `cargo test --all --all-features --locked --offline`（2,652件）、`cargo clippy --all-features --locked --offline --all-targets -- -D warnings`、Chrome上のfull（132件）・viewer（129件）のWASMテストを通過した。16小節の奏者別発音と、32小節の原案・区間変更後の再演をRust版と照合した。最適化後のfull WASMは8,726,563バイトで、既存上限8,740,000バイト以内。Linux・Windowsでの実行と奏者の独立評価は未確認。

## この先に広げる編曲

次の比較では編成を固定し、同じ8小節で音楽上の選択を一つずつ変える。順序はコード付け、伴奏、リハーモナイズとする。

1. **コード付け**　コードのない旋律から、終止をはっきりさせる案と、共通音を残して滑らかにつなぐ案を出す。ユーザーが固定したコードと終止位置を両案で照合する。
2. **伴奏生成**　採用したコードを固定し、低音と和音を交互に弾く案、持続音で支える案、句末だけ次の拍を先取りする案を比べる。弱起と反復の戻りで低音がずれず、旋律の休みに応答が収まることを確認する。
3. **リハーモナイズ**　変更を許した2小節だけにセカンダリードミナントやテンションを提案する。たとえばハ長調で次がGならD7→Gを候補にし、旋律とぶつかる音、次の和音への解決、低音・内声の移動、実際の楽器で出せる音を候補ごとに記録する。固定小節の演奏を照合し、候補と原案を同じ音色で試奏する。

この三つは次期候補とし、今回の試奏で判明した演奏不能箇所や記号欠落の修正を先に扱う。
