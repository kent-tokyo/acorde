# 和声・リズム・旋律を組み合わせる候補API

段階7の開発用 API。`suggest_integrated_arrangements` は、段階4の副属和音・転調候補、段階5のキックとベース、段階6の許可付き旋律先取りと対旋律変形を順に適用し、3〜5件の異なる再生結果を返す。`replay_integrated_arrangement` は保存した選択を元の楽譜と照合して再生成する。

## 指定と失敗条件

- `start_measure..end_measure_exclusive` は変更を許す物理小節範囲。和声・リズム・旋律の個別指定はこの範囲に一致させる。各技法の `locked_measures` も一致させる。
- `max_changed_harmonies`、`max_rhythm_attacks`、`max_melody_anticipations` はそれぞれの変更量上限。和声の探索制限や楽器音域・跳躍制限も各下位APIで守る。
- `rhythms` と `melodies` は各1〜5種類。`max_realizations` は最大125組み合わせ。探索上限に達して3案未満なら、見つかった件数と探索上限到達の有無を区別したエラーを返す。
- 候補は再生イベントの音高・時刻・音価・強弱で重複を除く。選択時には、和声、リズム、旋律の新しい差を優先する。`difference_codes` に基準案からの変更軸を記録する。
- 元のパートは、許可した主旋律の小節を除いて記譜を保持する。生成パートが対象範囲外で発音する候補は拒否する。失敗した組み合わせは `rejections` に理由を記録し、部分的な楽譜を返さない。

確定設定には三つの下位処理の解決済み設定と入力の識別情報を含む。候補探索を同じ入力でやり直して、保存した候補が引き続き選ばれる場合にだけ再生する。

## 検証状態

4小節の固定例で、和声・リズム・旋律の各軸を変えた3案、再生上の重複除去、保存設定からの再現、過大な変更量とロックの拒否を確認した。8小節の固定例では、対象外の小節の元記譜と、生成パートの無音を確認した。MusicXML と MSCZ の往復、WASM のネイティブ対応も局所テストで確認した。段階7の受け入れには8/16小節の試聴、Chrome full/viewer、全機能テスト、3 OS CI、容量と性能の比較が残る。
