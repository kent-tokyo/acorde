# 和声・リズム・旋律を組み合わせる候補API

段階7の開発用 API。`suggest_integrated_arrangements` は、段階4の副属和音・転調候補、段階5のキックとベース、段階6の許可付き旋律先取りと対旋律変形を順に適用し、3〜5件の異なる再生結果を返す。`replay_integrated_arrangement` は保存した選択を元の楽譜と照合して再生成する。

## 指定と失敗条件

- `start_measure..end_measure_exclusive` は変更を許す物理小節範囲。和声・リズム・旋律の個別指定はこの範囲に一致させる。各技法の `locked_measures` も一致させる。
- `max_changed_harmonies`、`max_rhythm_attacks`、`max_melody_anticipations` はそれぞれの変更量上限。和声の探索制限や楽器音域・跳躍制限も各下位APIで守る。
- `rhythms` と `melodies` は各1〜5種類。`max_realizations` は最大125組み合わせ。探索上限に達して3案未満なら、見つかった件数と探索上限到達の有無を区別したエラーを返す。
- 候補は再生イベントの音高・時刻・音価・強弱で重複を除く。和声設定のみを変えた案が得られたら、比較しやすい2案目として優先する。残りは新しい技法の軸と、選択済み案からの実発音上の距離で選ぶ。音符の増加数だけでは順位を決めない。
- `difference_codes` は選んだ技法の違い、`observed_difference_codes` は実際に変わった担当パートと発音上の違いを記録する。和声設定のみを変えても、それを参照するベースや対旋律の音高は変わり得る。`axis_distance_from_first` は和声の音高クラス、打点と音価、ベース、音域、担当の活動、記譜されたセクション境界の6軸を0〜1000のJaccard距離で示す。`nearest_selected_distance` は既に選んだ案への6軸距離の最小値。これらは聴感評価ではない。局所編集がセクション境界を保つ例では構成軸は0になる。
- 元のパートは、許可した主旋律の小節を除いて記譜を保持する。生成パートが対象範囲外で発音する候補は拒否する。失敗した組み合わせは `rejections` に理由を記録し、部分的な楽譜を返さない。

確定設定には三つの下位処理の解決済み設定と入力の識別情報を含む。候補探索を同じ入力でやり直して、保存した候補が引き続き選ばれる場合にだけ再生する。

## 検証状態

4小節の固定例で、和声・リズム・旋律の各軸を変えた3案、再生上の重複除去、保存設定からの再現、過大な変更量とロックの拒否を確認した。8/16小節では、基準案、和声設定のみを変えた案、リズムと旋律を変えた案を生成した。前者ではハーモニー・ベース・対旋律の発音が変わり、主旋律とキックは維持された。MusicXML と MSCZ の往復、WASM のネイティブ対応も確認対象にする。今回の実発音指標の追加後には、全機能テスト、3 OS、Chrome full/viewer、容量と性能を再測定する。音楽的な受け入れには更新した8/16小節パックの試聴が必要である。
