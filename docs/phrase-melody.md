# フレーズ旋律の許可付き先取り

開発ブランチの段階6 API。`arrange_phrase_melody(&Score, &PhraseMelodyRequest)` は、指定された主旋律の音を直前の休符へ先取りし、既存のモチーフ変形で対旋律パートを追加する。`replay_phrase_melody` は元楽譜の内容と保存した確定設定を照合して再生成する。

## 入力と出力

- `start_measure..end_measure_exclusive` は先取りを許す物理小節範囲。`locked_measures` はその範囲内でも変更しない小節。
- `anticipations` は音符住所、直前の休符住所、早める長さを指定する。長さは四分音符の1/32単位で、最初は音高を変えない。
- 両住所は同じパート・譜表・声部・小節で隣接する必要がある。休符を短く、次の音符を同じ長さだけ延ばすので、音符の終点と小節全体の長さは維持する。正確に書けない音価や休符の消失は型付きエラーにする。
- `countermelody_active_measures` は小節ごとの対旋律の有無。空配列は全小節で有効。`phrase_entry_max_leap_semitones` は休み明けの対旋律の跳躍上限で、最大24半音。
- `resolved` に入力の指紋、契約・エンジン版、許可内容、先取りした元音符IDを残す。`countermelody.generated_note_origins` は生成された各対旋律音と元モチーフ音の住所を対応付ける。

タイ、連符、歌詞、装飾や和音付きの主旋律音は、現行版では先取りを拒否する。休符側に別の記号がある場合も拒否する。連符や複雑な記譜を丸めて通さない。元楽譜は変更せず、失敗時には部分結果を返さない。

## 検証状態

4小節の固定例で、先取り前後の発音時刻・音価・音高、対象外の旋律と小節、対旋律の元音符対応、保存設定からの再現と変更検出を確認した。MusicXML と MSCZ の往復、WASM のネイティブ対応も局所テストで確認した。段階6の完了には、8/16小節の試聴、ブラウザーの full/viewer 実行、全機能テスト、3 OS CI、容量と性能の比較がさらに必要である。
